\title{Selection Beats Compression: Memory Decision Policies for Large
Language Model Agents Under a Bounded Store}

\author[nmims]{YASH RAMCHANDANI}
\author[nmims]{SIMAR SINGH KHANUJA}

\begin{abstract}
\textbf{Background.} Agents built on large language models (LLMs) accumulate
conversations far longer than any context window, so a memory layer must
decide what to keep, compress, forget and recall. Existing memory systems are
evaluated end to end, so the contribution of each decision is never measured
on its own, and the usual accounting bounds the context sent to the model but
leaves the store unbounded.

\textbf{Methods.} MemGate is an evaluation harness that sits between an agent
and a frozen LLM, isolates the memory policy and compares policies on a common
accuracy-per-token frontier, changing one factor at a time. It bounds the
store as well as the assembled context, in tokens or in bytes with the
embedding index included. Policies are evaluated on LoCoMo, REALTALK and BEAM
with paired bootstrap intervals clustered by conversation. The primary metric,
answer recall, checks that the answer text itself reaches the context, not
only the identifier of its turn. We compare a hand-written heuristic, a 0.5B
LLM judge and a logistic salience scorer over shallow features and a sentence
embedding, trained on generated and human conversations together.

\textbf{Results.} Bounding only the context charges a store-everything
baseline nothing for retention. With the store bounded, choosing which turns
to forget gains $+9.37$ answer-recall points over oldest-first eviction at
identical storage, fidelity and retrieval (95\% CI $[+5.45, +14.90]$), while
compressing evicted turns loses $7.13$ points, with no rate--distortion
crossover up to $182\times$ compression. A 1.5B model that rewrites evicted
turns narrows this gap but does not close it. Counting the embedding index
reverses the ranking below about 40\,KiB. The LLM judge loses to the
regular-expression heuristic by $5.87$ points, because salience is not a
property of a turn read on its own. The learned scorer beats the heuristic by
$+14.55$ points on held-out conversations, transfers from human to generated
dialogue but not the reverse, and outperforms MemGPT-style and Mem0-style
memory at every budget tested. On held-out chats of up to ten million tokens
it beats retrieval on every corpus; on million-token chats typed into the
application it keeps the answer for 51.9\% of questions against 19.2\% for
retrieval, and $+6.0$ points of its advantage become correct answers through a
fixed reader. Three results changed sign or size once a measurement error was
removed, and each was caught by an invariant rather than by reading the code.

\textbf{Conclusions.} Selection, not compression, is what a bounded memory
should spend its budget on, counted in bytes with the index included. The
policy ships as an offline chat application built on the experimental code,
which reproduces the retrieval and selection results at a 4096-token store
(28.1\% and 37.5\%) exactly.
\end{abstract}
